# Система метрик для шоукейса

## 1. Выбранные метрики

### Обязательная метрика
- `Median playtime` — медианное время одной игровой сессии.

Почему это важно:
- метрика показывает, насколько долго игроки реально остаются в билде;
- медиана хорошо подходит для шоукейса, потому что один очень короткий или очень длинный прогон не искажает результат так сильно, как среднее;
- по ней удобно быстро понять, удерживает ли билд внимание.

### Дополнительный KPI
- `Completed quests per session` — количество завершенных квестов за одну игровую сессию.

Почему это важно:
- это метрика реального прогресса, а не просто нахождения в игре;
- если `playtime` высокий, а квестов завершается мало, значит игроки блуждают, не понимают цель или упираются в фрикцию;
- если игроки быстро завершают хотя бы 1-2 квеста, значит onboarding, навигация и основной цикл работают лучше.

## 2. Как собираются метрики

В проект добавлен сервис [`SessionMetricsService`](/C:/UnityProjects/GitHub/Paws-Parcels/Paws-Parcels/Assets/Paws-Parcels/Scripts/Metrics/SessionMetricsService.cs), который работает так:

1. Игровая сессия начинается, когда активной становится сцена `Core`.
2. В этот момент создается новый `sessionId` и сразу записывается первый JSON-файл сессии.
3. Каждый раз, когда игрок завершает квест через [`QuestsService`](/C:/UnityProjects/GitHub/Paws-Parcels/Paws-Parcels/Assets/Paws-Parcels/Scripts/Quests/QuestsService.cs), сервис увеличивает KPI `completedQuestsCount` и перезаписывает JSON.
4. Когда игрок выходит из `Core` в другое меню/сцену или закрывает приложение, сессия завершается, и файл дописывается финальными значениями `playtimeSeconds`, `endedAtUtc`, `endReason`.

Такой подход полезен для шоукейса, потому что:
- каждая игровая попытка лежит в отдельном JSON;
- данные обновляются не только в конце, но и по ходу прохождения;
- папку с JSON можно просто собрать у тестировщиков и отдать парсеру.

## 3. Где лежат файлы

Сессии сохраняются в:

- `Application.persistentDataPath/Metrics/Sessions`

На Windows build это будет путь внутри пользовательской папки `AppData/LocalLow/...`, который Unity формирует сама. Точный корневой путь зависит от `Company Name` и `Product Name` в Player Settings.

## 4. Структура JSON-файла

Один файл = одна игровая сессия.

Пример структуры:

```json
{
  "SchemaVersion": 1,
  "SessionId": "d6c01b1d3f254f2f9417e64136b7c0f4",
  "SessionStatus": "completed",
  "StartSceneName": "Core",
  "StartedAtUtc": "2026-04-09T10:00:00.0000000Z",
  "LastUpdatedAtUtc": "2026-04-09T10:14:23.0000000Z",
  "EndedAtUtc": "2026-04-09T10:14:23.0000000Z",
  "PlaytimeSeconds": 863.24,
  "CompletedQuestsCount": 2,
  "CompletedQuestIds": ["1_Elk_to_Sova", "2_Owl_to_Puma"],
  "BuildVersion": "0.1",
  "ProductName": "Paws Parcels",
  "Platform": "WindowsPlayer",
  "EndReason": "application_quit"
}
```

Поля:
- `SessionId` — уникальный идентификатор сессии.
- `SessionStatus` — `in_progress` или `completed`.
- `StartedAtUtc` / `EndedAtUtc` — время старта и конца сессии в UTC.
- `PlaytimeSeconds` — длительность сессии в секундах.
- `CompletedQuestsCount` — число завершенных квестов за сессию.
- `CompletedQuestIds` — список id завершенных квестов.
- `EndReason` — почему сессия закончилась: выход из gameplay-сцены, закрытие приложения и т.д.

## 5. Как собрать датасет на 10+ сессий

Для ТЗ нужен минимум набор из 10 игровых сессий:

1. Дайте билд 10 игрокам или попросите нескольких людей пройти билд несколько раз.
2. После каждой игровой попытки заберите JSON-файлы из `Application.persistentDataPath/Metrics/Sessions`.
3. Сложите все завершенные файлы в одну папку.
4. Передайте эту папку парсеру.

Важно:
- в отчет по шоукейсу стоит брать только сессии со статусом `completed`;
- незавершенные сессии можно хранить для отладки, но в основной расчет KPI лучше не включать.

## 6. Как запускать парсер

Парсер лежит тут:

- [`metrics_parser.py`](/C:/UnityProjects/GitHub/Paws-Parcels/Paws-Parcels/Assets/Paws-Parcels/Tools/metrics_parser.py)

Пример запуска:

```bash
python Assets/Paws-Parcels/Tools/metrics_parser.py --input "C:\Path\To\Metrics\Sessions" --output "C:\Path\To\MetricsReport"
```

На выходе парсер создает:
- `sessions_table.csv` — плоская таблица по сессиям, удобная для Google Sheets / Excel;
- `quest_frequency.csv` — сколько раз каждый квест был завершен в датасете;
- `summary.json` — сводка по ключевым метрикам.

## 7. Что вставить в таблицы и диаграммы

Для отчета удобно построить:

- таблицу по всем сессиям из `sessions_table.csv`;
- столбчатую диаграмму `playtime_minutes` по сессиям;
- столбчатую диаграмму `completed_quests_count` по сессиям;
- отдельную карточку со значениями `medianPlaytimeMinutes` и `medianCompletedQuests` из `summary.json`.

## 8. Как анализировать результат

Примеры интерпретации:

- `median playtime` низкий и `completed quests` низкий: игроки быстро отваливаются, onboarding или первые цели недостаточно понятны.
- `median playtime` высокий, но квестов мало: игроки остаются в игре, но блуждают, путаются в маршруте или не считывают следующий шаг.
- `median playtime` средний, а квестов много: core-loop понятен, прогресс считывается, билд хорошо подходит для шоукейса.

## 9. Как можно улучшать значения метрик

Чтобы увеличить `median playtime`:
- сделать первые 30-60 секунд понятнее и насыщеннее;
- быстрее подвести игрока к первому понятному действию;
- убрать лишние паузы, непонятные состояния и фрустрирующие точки.

Чтобы увеличить `completed quests per session`:
- сильнее подсветить текущую цель на карте и в мире;
- сократить время между получением и сдачей первого квеста;
- упростить первый маршрут;
- убрать неоднозначные триггеры и неочевидные условия завершения;
- проверить, нет ли мест, где игрок может потерять темп из-за UI, камеры или транспорта.
