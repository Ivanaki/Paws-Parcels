# Используемый метод парсинга

## Метод

Для обработки данных используется **schema-based batch parsing**:

1. Парсер проходит по папке с игровыми сессиями и находит все `*.json`.
2. Каждый файл читается стандартным модулем Python `json`.
3. Данные нормализуются в единый формат:
   - `StartedAtUtc` и `EndedAtUtc` переводятся в ISO-8601 UTC;
   - `PlaytimeSeconds` приводится к `float`;
   - `CompletedQuestIds` приводится к списку строк;
   - `CompletedQuestsCount` берется из файла или восстанавливается по длине списка квестов.
4. По умолчанию парсер отбрасывает незавершенные сессии (`SessionStatus != completed`), чтобы аналитика по шоукейсу строилась только по валидным прогонам.
5. После нормализации парсер считает агрегаты:
   - медиану времени сессии;
   - среднее время сессии;
   - медиану завершенных квестов;
   - среднее завершенных квестов;
   - количество пустых сессий без прогресса.
6. Затем данные выгружаются в два слоя:
   - плоская таблица `sessions_table.csv` для ручного анализа и диаграмм;
   - сводка `summary.json` для итоговых значений KPI.

## Почему выбран именно этот метод

Преимущества метода:

- он простой и прозрачный, его легко описать в отчете;
- он устойчив к частично заполненным файлам;
- он не требует базы данных или внешнего сервиса;
- он хорошо подходит для маленького showcase-датасета на 10-30 сессий;
- итог легко импортируется в Google Sheets, Excel или DataLens.

## Особенность восстановления playtime

Основным источником длительности служит поле `PlaytimeSeconds`, которое уже пишет билд.

Если по какой-то причине этого поля нет, парсер может восстановить длительность как:

```text
EndedAtUtc - StartedAtUtc
```

Это делает парсер устойчивее к неполным данным и упрощает отладку.

## Что считается валидной сессией

Валидная сессия для анализа:

- содержит `StartedAtUtc`;
- корректно читается как JSON;
- имеет `SessionStatus = completed` или явно включена в анализ через флаг `--include-in-progress`.

Если файл поврежден или не соответствует схеме, он не ломает весь датасет: парсер пропускает его и записывает причину в `summary.json`.
